contract: 0xd45884b592e316eb816199615a95c182f75dea07 (non-proxy)

The `solver` argument is caller-supplied and is NEVER required to equal msg.sender.
Loop 2 executes  want.safeTransferFrom(solver, users[i], assetsToUser)  which pulls the WANT
token out of `solver` using solver's standing approval to the queue. By naming a victim as
`solver`, and placing a self-request that offers a worthless token and wants the victim's token,
the attacker redirects the victim's stale approval to themselves.

Note the finishSolve call between the two loops:
  IAtomicSolver(solver).finishSolve(runData, msg.sender, offer, want, assetsToOffer, assetsForWant);
This high-level external call reverts on a code-less address, so only a `solver` WITH code
(a contract or an EIP-7702-delegated account) can be drained via this path.
