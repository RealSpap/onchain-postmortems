Neither address matches the confirmed cbETH attacker
(0x6F2f5236b10FE7162Da077A2779f8b5f04b7827e, nonce 10, plain EOA) or its
exploit contracts. Both have substantially higher transaction counts than
the confirmed attacker's fresh wallet.

Two readings, both plausible, neither confirmed:
  1. Unrelated liquidation-keeper bots. A high nonce and a tiny
     minimal-proxy contract are exactly the signature of automated
     liquidation infrastructure that has been running across many
     protocols for a while; Ajna's own Kick function is permissionless
     and incentivized (pays a bond/reward to whoever calls it), so a
     routine keeper bot calling Kick on multiple pools in the same hour
     is not inherently suspicious on its own.
  2. Copycat exploiters. Once the first pool's Kick/AuctionSettle
     transactions landed on-chain (public mempool and/or block explorers),
     the same broken accounting pattern would have been visible to anyone
     inspecting the transaction, and a second or third opportunist could
     have redeployed a similar exploit against other pools within
     minutes to hours, which is consistent with the timing observed here.

This project did not trace either address's history on other protocols
deeply enough to settle which reading is correct, and reports both rather
than asserting one as fact. See README caveats.
