--- 4. press coverage read AFTER the reconstruction ---
  Web search for 'Internet Token Base exploit September 2026'. The aggregated
  summaries returned describe: a LiquidityUnifier that trusts a pool address
  supplied by the caller, a fake pool callback that mints about
  925 million INT, 5.847 WETH or about $16,033.55 taken out of the
  official INT/WETH pool, about 764 million INT kept, a mint role
  not revoked in time, copycats that push the supply to about
  156 billion, and a governance proposal by the attacker targeting the
  treasury. Total reported loss: about $265,000.
  What checks out on-chain: the LiquidityUnifier name, the caller-supplied
  pool, the mint amount, the WETH taken, the INT kept, and the supply peak
  at 156 billion (156,277,572,881 INT exactly).
  What does not check out: the $265,000 loss (the pool only held
  5.847033390701967596 WETH in total), and the governance proposal, which
  this entry does not assert since it did not reconstruct it.
  What the press does not say at all: the mint alone yields nothing, it is
  undone by validateSupply and by _clearPool in the same transaction. Without
  the Convertor there is no exploit. One transaction proves it:
  0x0af9d052... minted about 2**224 wei and its supply delta is zero.

--- 6. Convertor's verified source, in full, 38 lines ---

    contract Convertor is ReentrancyGuard {
        using SafeERC20 for IERC20;
    
        IERC20 public immutable transferrableToken;
        RewardToken public immutable mintableToken;
    
        constructor(
            IERC20 _transferrableToken,
            RewardToken _mintableToken
        ) {
            transferrableToken = _transferrableToken;
            mintableToken = _mintableToken;
        }
    
        function convert(address from, uint256 amount) external nonReentrant {
            if (from == address(transferrableToken)) {
                transferrableToken.safeTransferFrom(msg.sender, address(this), amount);
                mintableToken.mint(msg.sender, amount);
                return;
            }
    
            if (from == address(mintableToken)) {
                mintableToken.burn(msg.sender, amount);
                transferrableToken.safeTransfer(msg.sender, amount);
                return;
            }
    
            revert("invalid from token");
        }
    }
    (end of extract)
    Key point: convert is external and carries no role modifier.
    The contract itself holds TOKEN_MINTER and TOKEN_BURNER on INT, so
    any caller can make the round trip in both directions.
