--- 4. couverture de presse lue APRES la reconstruction ---
  Recherche web sur 'Internet Token Base exploit September 2026'. Les resumes
  agreges renvoyes decrivent : un LiquidityUnifier qui fait confiance a une
  adresse de pool fournie par l'appelant, un faux callback de pool qui minte
  environ 925 millions d'INT, 5,847 WETH soit environ 16 033,55 $ sortis du
  pool officiel INT/WETH, environ 764 millions d'INT gardes, un role de mint
  non revoque a temps, des copieurs qui portent la supply a environ
  156 milliards, et une proposition de gouvernance de l'attaquant visant la
  tresorerie. Perte totale annoncee : environ 265 000 $.
  Ce qui se verifie sur la chaine : le nom LiquidityUnifier, le pool fourni
  par l'appelant, le montant du mint, le WETH sorti, l'INT garde, et le pic
  de supply a 156 milliards (156 277 572 881 INT exactement).
  Ce qui ne se verifie pas : la perte de 265 000 $ (le pool ne contenait que
  5,847033390701967596 WETH en tout), et la proposition de gouvernance, que
  cette entree n'affirme pas puisqu'elle ne l'a pas reconstruite.
  Ce que la presse ne dit pas du tout : le mint seul ne rapporte rien, il est
  annule par validateSupply et par _clearPool dans la meme transaction. Sans
  le Convertor il n'y a pas d'exploitation. Une transaction le prouve :
  0x0af9d052... a minte environ 2**224 wei et son delta de supply est nul.

    contract Convertor is ReentrancyGuard {
        using SafeERC20 for IERC20;
    
        IERC20 public immutable transferrableToken;
        RewardToken public immutable mintableToken;
    
        constructor(
            IERC20 _transferrableToken,
            RewardToken _mintableToken
        ) {
            transferrableToken = _transferrableToken;
            mintableToken = _mintableToken;
        }
    
        function convert(address from, uint256 amount) external nonReentrant {
            if (from == address(transferrableToken)) {
                transferrableToken.safeTransferFrom(msg.sender, address(this), amount);
                mintableToken.mint(msg.sender, amount);
                return;
            }
    
            if (from == address(mintableToken)) {
                mintableToken.burn(msg.sender, amount);
                transferrableToken.safeTransfer(msg.sender, amount);
                return;
            }
    
            revert("invalid from token");
        }
    }
    (fin de l'extrait)
    A retenir : convert est external et ne porte aucun modificateur de role.
    Le contrat detient lui-meme TOKEN_MINTER et TOKEN_BURNER sur l'INT, donc
    n'importe quel appelant peut faire l'aller-retour dans les deux sens.
