# On-Chain Postmortems

*One question for every on-chain incident: what made it possible, and which check was missing?*

**$954.3M in DeFi and on-chain losses across 72 incidents, 71 of them reconstructed from raw chain data (the exception, tectonic-cronos, is not: per Cronos's report the chain was rolled back past it); $617.4M of it independently recomputed, the rest sourced from the protocol, press or DefiLlama.**

Forensic reconstructions done on-chain. Each entry rebuilds the exploit
from raw chain data (`eth_getLogs`, decoded transaction receipts,
`eth_call` reads) rather than from press summaries. When press or
DefiLlama gets a number, scope, or label wrong, this repo shows the
on-chain proof; when a dollar figure could not be recomputed, the Index
says so and marks it †.

This is research for defenders. Each entry rebuilds a past incident from public chain data, so a team can see which control would have mattered. It is not a guide to attacking anything, and nothing here holds funds, keys or a way to move money.

## Start here, in 60 seconds

1. **Read one incident.** Open [`incidents/sandbox-oft-delegate-hijack/`](incidents/sandbox-oft-delegate-hijack/). Press reported only the Ethereum leg of the Sandbox bridge exploit; the reconstruction finds the gross amount across Base and Ethereum to be about five times the press figure, one of 38 rows in [Corrections to press and DefiLlama](CORRECTIONS.md).
2. **Don't trust me. Redo it.** Every entry but one rebuilds its incident from public chain data, and its script reads the chain live. The exception is tectonic-cronos: per Cronos's report the chain was rolled back past that attack, so its README says which parts rest on Cronos's report and Certora's analysis. Try one against a public RPC:

   ```bash
   python3 incidents/sandbox-oft-delegate-hijack/reconstruct_exploit.py
   ```

   It needs `web3` (`pip install web3`).

   The historical figures should match `incidents/sandbox-oft-delegate-hijack/resultats_reconstruction_2026-09-09.txt`; balances and roles read today may have moved since. A difference is useful: see [CONTRIBUTING.md](CONTRIBUTING.md).
3. **See what I got wrong.** [CORRECTIONS.md](CORRECTIONS.md) opens with my own errors, dated, before it lists anyone else's.
4. **Find the incidents that look like your protocol.** Pick a type below, or run `python3 tools/find_incidents.py --category Bridge --chain Ethereum`.

## How to read an incident

1. Start with [INDEX.md](INDEX.md): every incident by year and month, with its loss, chain, category and mechanism.
2. Open the incident folder under [`incidents/`](incidents/). Its `README.md` is the write-up: an "at a glance" block, the method, the caveats.
3. Check the numbers yourself: `reconstruct_exploit.py` re-queries the chain, `resultats_*.txt` is the saved output it should match, and `registre_hypotheses.csv` lists every claim with the test that would falsify it.
4. The marks in the Index: **≥** known floor, **≈** recomputed, **†** sourced, not recomputed. More in [docs/method.md](docs/method.md) and [docs/limits.md](docs/limits.md).

## Contribute

Five first tasks are in [CONTRIBUTING.md](CONTRIBUTING.md). The short version:

- **A figure is wrong, or a statement is unfair:** open an issue with the "A figure is wrong" form, or write privately (see [SECURITY.md](SECURITY.md)).
- **An incident is missing:** open an issue with the "Suggest an incident" form: protocol, date, chain and, if you have it, a transaction hash.
- **Replay an entry or send a fix:** `python3 tools/check_readme_consistency.py` and `python3 tools/check_structure.py` must pass before a pull request.

New incidents are announced as GitHub releases (Watch, then Custom, then Releases), or through the plain [Atom feed](https://github.com/RealSpap/onchain-postmortems/releases.atom), no account needed.

## Structure

- **Root:** `README.md`, `INDEX.md` (every incident), `CORRECTIONS.md`, `CHANGELOG.md`, `SECURITY.md`, `CONTRIBUTING.md`, `CITATION.cff`, `LICENSE`.
- **`incidents/`:** one folder per incident, with its write-up, its script, its registry of hypotheses and the raw output.
- **`tools/`:** replay checks, the incident finder, the dataset export, the structure check.
- **`data/`:** the dataset, machine-readable. **`digests/`:** monthly roundups.
- **`docs/`:** method, limits, and the by-type index.
- **Old paths:** the old incident folders and script names at the root are short redirects to `incidents/` and `tools/`, kept so links published before the move keep working; they are listed in `tools/structure.json`.
